# Cloud Asset Pipeline (Module 13)

The Cloud Asset Pipeline is a secure, provider-agnostic engine designed to process, store, validate, and manage the lifecycle of creative assets generated by AI models or uploaded directly by users.

## Architectural Architecture

```
User Upload / Provider Job Complete
              ↓
      [Ingestion Stage] (Checksum + MIME Detection)
              ↓
     [Processing Pipeline] (Hashing, Transcoding, Curation)
              ↓
           [Ready] (Registered in Creative Library)
          ↙       ↘
     [Archived]    [Deleted] (Compliance Checked)
```

## State Machine Rules

Assets proceed through strict state transitions defined in `/src/features/asset-pipeline/assetPipeline.ts`:

- `pending` / `ingesting` ➔ `processing` ➔ `ready`
- `pending` / `ingesting` / `processing` ➔ `failed`
- `ready` ➔ `archived`
- `archived` ➔ `ready`
- `ready` / `failed` / `archived` ➔ `deleted`

## Storage Agnosticism

The storage layout is abstracted from physical cloud providers. It uses:
- `bucket`: The cloud target container.
- `storageKey`: The deterministic, non-clashing target path (`workspaces/{ws}/assets/{id}/original`).
- `storageProvider`: Decoupled identifier (e.g. `mock`, `s3`, `gcs`).

## Compliance Controls

- **Retention Schedule**: Restricts asset deletion before calculated `retentionUntil` timestamps.
- **Legal Hold**: Prevents deletion under any condition unless forced.
- **Interrupted Safeguard**: Restoring backups automatically switches incomplete ingestions to a cleanly logged `failed` state.
